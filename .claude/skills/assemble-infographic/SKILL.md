# Assemble Infographic

Four Pillars 테마로 생성한 투명 배경 차트를 기준 템플릿에 조립한다. 차트를 새로 그리는 스킬이 아니며, 차트가 없으면 먼저 `/chart --theme four-pillars` 흐름을 완료한다.

## 입력 계약

- `chart.svg`: 조립할 최종 차트 SVG
- `title`: 사용자가 차트 요청에서 준 문구를 유지하되, 모든 단어의 첫 글자를 대문자로 변환한다. 나머지 글자는 강제로 소문자로 바꾸지 않아 브랜드, 티커, 수치 내부 표기를 보존한다
- `subtitle`: 사용자가 차트 요청에서 준 문구를 유지하되, title과 동일하게 모든 단어의 첫 글자를 대문자로 변환한다. 나머지 글자는 원래 대소문자를 유지한다
- `source`: 실제로 차트 데이터에 사용한 출처만 적는다. 추측하거나 새 출처를 만들지 않는다
- `date`: 데이터에 포함된 마지막 날짜만 사용한다. 시작일이나 전체 기간을 넣지 않는다
- `note`: 선택 항목. 사용자가 주지 않았으면 만들지 않는다
- `legend`: 선택 항목. 시리즈마다 표시명, 실제 색상, 기호 유형을 전달한다

제목과 부제목의 문구를 임의로 다시 쓰지 않는다. 단, 메인 제목과 부제목은 모두 모든 단어의 첫 글자를 대문자로 변환한다. 공간이 부족하면 줄바꿈이나 영역 배치만 조정한다.
제목 줄바꿈은 문법적 의미 단위와 문장 호흡을 먼저 보존하고, 그 안에서 각 줄의 길이를 가능한 한 균형 있게 맞춘다. 전치사는 뒤의 목적어와 같은 줄에 두어 전치사구를 보존하며, 관사와 접속사도 줄 끝에 홀로 남기지 않는다. 월과 연도(`Aug 2026`), 수치와 단위(`$269M`), 고유명사처럼 함께 읽히는 표현을 서로 다른 줄로 분리하지 않으며 마지막 줄에 한 단어만 남기지 않는다.
최종 SVG와 PNG의 파일명은 내부 작업용 슬러그가 아니라 인포그래픽에서 가장 크게 표시되는 `title` 문구를 사용한다. 파일시스템에서 사용할 수 없는 `/` 같은 문자는 `-`로 바꾸고 파일명 끝의 문장부호는 생략한다. 피그마에서 가져왔을 때 레이어 이름이 차트 제목으로 보이게 하기 위한 규칙이다.

템플릿의 폰트와 지정 폰트 크기는 불변이다. Title 50px, Subtitle 38px, 범례 28px, Note/Source/Date as of 라벨 22px, 각 내용 28px을 사용한다. 문구가 길면 지정 크기를 줄이지 말고 줄바꿈 또는 영역 배치로 해결한다.
인포그래픽에 들어가는 차트의 X축·Y축 눈금 라벨은 16px을 기본값으로 사용한다. 두 축의 크기는 동일하게 유지한다.
부제목의 왼쪽 끝은 현재 배치된 차트의 Y축 눈금 라벨이 시작하는 실제 왼쪽 끝과 일치시킨다. SVG 외곽이나 플롯 그리드 시작점에 맞추지 않는다.
부제목은 Pretendard Medium, font-weight 500을 사용한다. Bold 또는 SemiBold로 바꾸지 않는다.

## 표기 규칙

- Date as of: 데이터 종료일만 `Sep 21, 2026` 형식으로 표시한다
- 기간형 데이터도 시작일과 구분자를 적지 않고 마지막 날짜만 표시한다
- Source 값: `DefiLlama, Artemis`처럼 출처명만 쉼표로 구분한다. 스크립트가 `Source` 라벨을 별도로 그린다
- Note가 없으면 템플릿의 Note placeholder를 제거하고 빈 공간으로 둔다
- Source, Date as of, Four Pillars 로고는 템플릿의 절대 위치를 그대로 유지한다. Source와 Date는 값 placeholder만 교체하고 라벨, 구분선, 상위 그룹에는 이동이나 transform을 적용하지 않는다. 로고 그룹은 내용과 좌표를 수정하지 않는다

## 범례 규칙

차트 SVG 자체에는 범례를 넣지 않는다. 인포그래픽 조립 단계에서 차트에 실제로 사용한 시리즈명과 색상으로 범례를 만든다.

- 일반 실선 라인: `line`, 얇은 둥근 막대 기호
- 점선 또는 파선 라인: `dashed`, 점선 기호
- 막대, 누적 막대, 영역, 누적 영역, 산점도, 파이, 도넛 및 그 밖의 유형: `square`, 둥근 사각형 기호
- 범례 자산의 크기와 범례 글자 크기는 불변이다. 배치 공간에 맞추려고 확대하거나 축소하지 않는다
- 아이콘과 글자가 나란히 놓이는 범례는 두 요소의 세로 중심을 동일한 Y좌표에 맞춘다
- 원본 시리즈가 5개를 넘으면 표시 기간 전체 합계 기준 상위 5개만 유지하고, 나머지는 각 시점별로 합산한 `Others`로 차트 자체를 다시 그린다
- 범례도 다시 그린 차트와 동일한 상위 5개와 `Others`만 사용한다. 최대 항목 수는 6개다. 일반 순서에서는 `Others`를 마지막에 두고, 누적 차트의 역순 범례에서는 첫 번째에 둔다
- `Others`는 기본 중립 회색 `#777B80`을 사용한다
- 시리즈 순서는 차트의 시각적 순서를 따른다. 누적 막대와 누적 영역 차트는 스택의 위쪽 레이어부터 아래쪽 레이어 순으로 범례를 배치하므로, 차트를 그릴 때 사용한 시리즈 순서의 역순으로 전달한다
- 표시명은 사람이 읽을 수 있게 쓰고, Title과 Subtitle처럼 모든 단어의 첫 글자를 대문자로 변환한다. 나머지 글자는 원래 대소문자를 유지한다
- 각 항목은 `--legend "Label|#RRGGBB|style"` 형식으로 반복 전달한다
- `--legend-position auto`가 기본값이다. 넓고 낮은 차트는 차트 아래, 상대적으로 세로 공간이 있고 우측 영역을 확보할 수 있는 차트는 오른쪽에 둔다. 차트 위에는 범례를 두지 않는다
- 오른쪽형은 SVG 전체 높이가 아니라 실제 플롯의 Y축 범위를 사용한다. 6개 항목의 첫 상단과 마지막 하단이 Y축 범위를 넘지 않게 균등 배치한다
- 시각 판단과 자동 선택이 다르면 `--legend-position right` 또는 `--legend-position bottom`으로 지정한다

레이아웃 좌표와 세부 검수 기준은 [references/template-rules.md](references/template-rules.md)를 따른다.

## 실행

프로젝트 루트에서 실행한다.

```bash
.venv/bin/python .claude/skills/assemble-infographic/scripts/assemble.py \
  outputs/charts/{topic}/{chart}.svg \
  "outputs/infographics/{topic}/{title}.svg" \
  --title "{request title}" \
  --subtitle "{request subtitle}" \
  --source "{actual sources}" \
  --date "{formatted data end date}" \
  --legend "Series A|#55D292|line" \
  --legend "Series B|#D78C2F|square" \
  --legend-position auto
```

Note가 명시된 경우에만 `--note "..."`를 추가한다. 스크립트는 최종 SVG와 같은 경로에 PNG도 만든다.

## 완료 전 검수

1. 생성된 PNG를 Read로 연다.
2. 제목과 부제목이 요청 문구와 같은지 확인한다.
3. 제목 줄바꿈이 의미 단위를 끊지 않고, 줄 길이가 균형적이며, 마지막 줄에 한 단어만 남지 않는지 확인한다.
4. 차트가 찌그러지거나 잘리지 않았는지 확인한다.
5. X축·Y축 눈금 라벨이 모두 16px이며 잘리지 않고 읽히는지 확인한다.
6. 제목, 차트, Source, 날짜, 로고가 서로 겹치지 않는지 확인한다.
7. Source와 날짜가 실제 데이터와 일치하는지 확인한다.
8. 범례의 시리즈명, 색상, 기호 유형, 순서가 실제 차트와 일치하는지 확인한다.
9. 원본 시리즈가 5개를 넘었다면 차트와 범례 모두 상위 5개와 `Others`로 구성됐는지 확인한다.
10. 아래 배치에서는 범례가 반드시 차트의 하단보다 아래에 있는지, 오른쪽 배치에서는 모든 범례가 실제 Y축 범위 안에 있는지 확인한다.
11. 문제가 있으면 범례 위치, 줄바꿈 또는 좌표를 조정해 다시 실행한다. 폰트, 폰트 크기, 범례 자산 크기는 변경하지 않는다. 최대 3회까지만 반복한다.

검수를 통과한 경우에만 최종 SVG와 PNG 경로를 반환한다. 해결되지 않은 겹침이나 잘림이 있으면 결과물을 보존하고 `NEEDS_REVISION`으로 보고한다.
